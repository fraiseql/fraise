## Judgements taken in Cycle 1

**Where the refusal class lives.** The plan writes the refusal as "exit 5", and no class name
or wire integer may be written in this crate's source (Phase 02, Cycle 2). The face's own
refusals now live in the face's section of the vendored contract —
`mappings.refusals` in `exit_table.vendored.json` — beside the readings of each tool's exits,
because a refusal *is* a reading of that contract: `invalid_configuration` reads as
`invalid_config`, `compatibility_unsatisfied` as `precondition_failed`. `compatibility.toml`'s
`[refusal]` section moves there, so exactly one document in the tree names a class, one loader
resolves every name against the `classes` list, and a refusal the contract cannot give an exit
to fails at load. The source names refusals, never classes.

**What `[environments]` may hold.** One field, `database_url_env`, and it is the *name* of an
environment variable: `[A-Z_][A-Z0-9_]*`, the same strict form confiture's `${VAR}` accepts.
That one rule is what refuses a DSN — a connection string in a committed file is what this
face exists to prevent, and the test says so in those words — and it also refuses a
`${DATABASE_URL}` reference, a lowercase name and an empty string. The refusal names the key
and, for a value holding `://`, says that a connection string is not the name of a variable.

**How `show --json` redacts without becoming a second serialiser.** It does not render a
resolved value at all. `show` prints the document *as written* — so a value that came from the
environment appears as the `${VAR}` reference the file holds — plus a `from_env` map of
document path to the variables that fed it. Nothing has to be masked, an agent is told which
variable to set, and the payload is a `serde_json::Value` handed to the envelope exactly as
`doctor`'s report is, so `serde_json::to_string` still appears in one file. Which is what
`envelope.rs`'s one-serialiser test holds.
